## Deferred technical debt

- Accepted `DetectedRegion`s are not yet wired into `quantityEngine.js`/`ExportButton.jsx` — the release gate's actual requirement (quantity is never *automatically* modified) holds structurally without this integration; consuming accepted regions in the export pipeline is deferred, documented explicitly in the architecture doc.
- The 0.65 candidate threshold and 0.5 evidence-coverage floor are calibrated against the synthetic benchmark plus one real fixture page, not a large real-plan corpus — flagged as a real limitation, not silently assumed sufficient.
- `MAX_TILES_PER_RUN` (4000) is a safety cap, not a scaling solution for arbitrarily large pages.
- No visual similarity-heatmap UI was built (correctly deferred per R6's own explicit scope boundary — the backend `TileEvaluation` representation is the required first step, not a rendered heatmap).

## Risks before R7

- The real-plan false-positive finding (title text / description-box border scoring as candidates) suggests the current threshold may need real-corpus-driven recalibration before a wider rollout — a future release should validate against more real, varied plans before loosening any review-layer expectations.
- `DetectedRegion` and the legacy MVP's own in-browser detection review are two separate, non-unified review experiences now — a future release should decide whether to consolidate them rather than let both grow independently.
- Detection is currently synchronous; if real usage produces materially larger pages or reference patterns with much higher detected-line-count tiles than anything measured here, the performance numbers in this document should be re-validated before assuming they still hold.
