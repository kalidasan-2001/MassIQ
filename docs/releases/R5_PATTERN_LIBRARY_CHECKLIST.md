## Similarity engine — angle, spacing, density, cross-hatch, periodicity, line width, color

**PASS**, each independently unit-tested (`backend/tests/test_similarity_*.py`, 34 tests across 7 component modules):
- **Angle**: circular-distance wraparound verified (179°/1° close), 45°/135° correctly maximally dissimilar on their own, multi-angle best-pairing verified (`[45,135]` vs `[135,45]` scores perfect), count-mismatch handling documented and tested.
- **Spacing**: smooth relative-difference formula, R4's own measured ~15% same-pattern scale deviation verified to score >0.8 similarity (not penalized as a different pattern).
- **Density/periodicity**: bounded absolute difference; periodicity's regular-vs-irregular-control test (R5 section 16's explicit requirement) passes with a real, meaningful similarity loss.
- **Cross-hatch**: clean 1.0/0.0 agreement, missing-evidence (`None`) correctly excluded; combined-score test proves one disagreeing boolean cannot zero the overall similarity (stays >0.85 when everything else matches).
- **Line width**: missing-on-either-side excluded, never substituted with zero (literal R5 section 18 requirement, tested directly).
- **Color**: CIE76 LAB distance, always available, real-measured same-pattern brightness variation scores >0.9.

## Deferred technical debt

- `evidence_coverage`'s 0.5 threshold for the HIGH-band cap is a documented, evidence-informed choice (calibrated against the one negative-control case the benchmark surfaced), not exhaustively tuned across many real scenarios — revisit if real usage surfaces a case it handles poorly.
- No deactivate/delete endpoint for `PatternLibraryEntry` exists yet; the `active` column exists specifically so a future release can add one without a second migration.
- `LegendWorkspace.jsx`'s pre-existing R4 hatch-features fetch effect (`getHatchFeatures`) still has no explicit `.catch()` of its own, unlike the new R5 decision-restore effect — not touched in R5 since it is pre-existing R4 code with no observed failure, and fixing code outside this release's stated scope was avoided; flagged here for whoever next touches that file.
- Real-crop validation remains scoped to a single real construction plan (same limitation as R4) — a future release should source additional real plans/projects before trusting cross-plan library behavior beyond what this document shows.

## Risks before R6

- The ranking benchmark's 100% Top-1/Top-3 result is measured on synthetic fixtures that are, by construction, cleanly separated on the two highest-weighted features (angle, spacing) — this is evidence the weights are not obviously wrong, not proof they are optimal for messier real-world hatch variety. A future release building on this scoring should gather more real comparison data before trusting it at face value.
- `evidence_coverage` is new, R5-specific quality metadata with no precedent in R4 — any future consumer of `SimilarityResult` must understand it is not a confidence score and must not assume every "high similarity" number is equally well-supported without checking it.
- The cross-hatch disagreement observed between two crops of the literal same real wall (see benchmark doc section 6) is a reminder that real scan noise can flip a boolean structural classification even for genuinely identical underlying material — any future feature built on `is_cross_hatch` alone should account for this.
